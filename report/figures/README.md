## 2. Screenshots — capture from the lab

**41 slots, `SS-01` to `SS-41`.** The full list with the caption each one carries in
the report is in [`../../verification/CHECKS.md`](../../verification/CHECKS.md) §12.

Name them `SS-nn-<slug>.png`, matching the slug in that index — for example
`SS-07-ospf-neighbors.png`. The report and the verification plan both reference these
names, so correct naming at capture time means no renaming later.

### Capture guidance

- **Whole window, not a crop.** Include the device prompt (`HQ-CORE#`) and the command
  that produced the output. A cropped table of numbers proves nothing about which
  device it came from.
- **Timestamps help.** Where a command reports time, leave it visible — it corroborates
  the syslog and NTP evidence.
- **Failures are evidence too.** Section 6 of the verification plan expects traffic to
  be *blocked*. Capture the refusal message, and capture the matching ACL counter or
  log entry alongside it. A failed ping on its own is indistinguishable from a broken
  network; a failed ping plus an incrementing deny counter is proof of policy.
- **Readability.** Increase the console font before capturing. A screenshot that has
  to be zoomed to read costs marks in a printed document.
- **PNG, not JPEG.** Terminal text compresses badly in JPEG.

If time is short, these carry the most weight because each proves something the design

| Slot | Why it matters |
|------|----------------|

| `SS-12` | Primary path preferred over the cost-50 backup; proves the cost engineering works |
| `SS-22` + `SS-25` | Guest blocked from five destinations, **and** still able to resolve names. The pair proves isolation is selective rather than the network being broken |
| `SS-23` | Guest containment holding during WAN failover, with counters on `HQ-CORE` |
| `SS-31` | Several sources sharing one inside global address — proves PAT rather than one-to-one NAT |
| `SS-32` | Inbound published service reaching `WEB-SRV` — the path that was previously non-functional |
